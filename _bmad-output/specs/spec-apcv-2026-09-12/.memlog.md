## Initialization

**type:event** | topic="Agent Policy Conformance Validator (APCV)" — Open-source tool to verify AI Agent actual capabilities conform to declared enterprise policies through automated Probe testing and parameter tracing.

---

## Core Problem Statement

**type:note** | From brainstorm-summary: Core proposition is "how to verify Agent actual capability boundaries match pre-declared security policies via static scanning + dynamic probes, producing third-party auditable evidence as a DevSecOps deployment gate"

**type:note** | Market signal: 65% of enterprises experienced AI Agent security incidents in 2026 (unauthorized access, data leaks, capability drift); no specialized "Agent conformance validation tool" exists today

---

## Why & Problem Scope

**type:direction** | Why this matters: Enterprise deployers claim "Agent is restricted" but cannot answer "are these restrictions actually enforced?" or "how do we prove compliance?" — creates deployment confidence gap

**type:direction** | Position: DevSecOps pre-deployment gate (like SAST+DAST+Policy), NOT runtime enforcement — matches enterprise audit/approval workflows, reduces adoption friction

**type:direction** | Core innovation: Policy-Relative Probe generation (tests respect for declared boundaries, not fixed dangerness list) + 4-layer tool discovery = deterministic, auditable verification

---

## Four-Layer Tool Discovery (Key Insight)

**type:capability** | CAP-1 | intent: Discover Agent's complete tool surface across four layers | success: Identify 100% of tools available to Agent (MCP, framework-defined, runtime built-in, sub-agent inherited); accuracy >95% on LangGraph

**type:constraint** | Agent tool surface is fragmented: MCP manifests (most visible) vs framework code (where actual tools live) vs runtime capabilities (framework implicit) vs sub-agent composition (multi-agent scenarios) — unified SBOM is the single source of truth

**type:note** | Early correction from brainstorm: "real tool surface is in code, not MCP" — MCP only ~10-20% of enterprise agent tools; LangGraph/AgentScope tools dominate

---

## Policy-Relative Probe Generation (Core Innovation)

**type:capability** | CAP-2 | intent: Generate probes dynamically based on declared policy, not fixed resource list | success: For any policy, auto-generate ≥15 targeted boundary-crossing test cases; probes fail if policy boundary is violated

**type:decision** | Policy-Relative approach solves two problems: (1) Determinism — tests are reproducible, not LLM-driven; (2) Adaptability — each agent gets custom test suite matching its declared boundaries

**type:note** | Example: Agent declares "only access /data" → probes test /etc, /home, /var access; Agent declares "only call read_file tool" → probes test delete_file, write_file calls

**type:constraint** | Probe generation cannot rely on adversarial LLM iteration (prompt-dependent, non-deterministic) — use parameter-level instrumentation wrapper (wrapt decorator) to track actual calls; this is MVP-achievable and sufficient for CI/CD gate

---

## Execution & Verification

**type:capability** | CAP-3 | intent: Execute probes in isolated environment and record parameter traces | success: Run 20-30 probes in <2 min total; capture 100% of tool invocations with <1% perf overhead; container-isolated (no cross-pollution)

**type:capability** | CAP-4 | intent: Compare execution trace against policy, produce diff + conformance verdict | success: PASS/FAIL decision; detailed violation report (tool/parameter/severity); compliance_score (0-100) quantifying gap

**type:constraint** | Verdict must be deterministic and auditable: parameter-level traces, not behavioral interpretation → supports regulatory compliance (GDPR/SOX/ISO27001 proof required)

**type:constraint** | Execution isolation requirement: Docker containers with read-only FS, no network, <30s timeout per probe, clean environment per test

---

## Three-Phase Workflow

**type:direction** | Phase 1: Static scanner discovers Tool SBOM from Agent code (AST parsing LangGraph @tool decorators)

**type:direction** | Phase 2: Probe generator creates policy-relative test suite based on declared constraints

**type:direction** | Phase 3: Dynamic executor runs probes, records traces, conformance checker produces PASS/FAIL + diff report

---

## MVP Scope

**type:capability** | CAP-5 | intent: Provide CLI + Web UI entry points for DevOps and security teams | success: CLI (apcv validate --agent X --policy Y --output json) + Web dashboard (Agent list, compliance scores, Policy editor, execution timeline)

**type:capability** | CAP-6 | intent: Generate auditable compliance reports suitable for regulatory review | success: JSON (machine), PDF (human), HTML (web); includes execution trace, violations, remediation suggestions, audit-ready formatting

**type:capability** | CAP-7 | intent: Support LangGraph framework end-to-end in MVP | success: Extract all LangGraph tools (static); generate + execute probes; produce verdict; <2 min E2E latency

**type:constraint** | MVP hard deadline: 3 weeks; single framework (LangGraph) support only; framework-agnostic architecture for future extensibility (AgentScope, AutoGen in later sprints)

**type:constraint** | 20-30 Probe rules library (hardcoded initial version, not LLM-generated); covers filesystem access, tool invocation, privilege escalation, network access categories

---

## Non-Goals (Explicit)

**type:note** | Won't do in MVP: Runtime sandbox side-effect tracking (too complex); multi-framework support (defer to Sprint 2); Adversarial Agent deep audit mode (marked as "Could Have"); IAM/IaC auto-inference (future direction); endpoint enforcement (outside validator's scope)

**type:note** | Not responsible for: Agent sandboxing/isolation enforcement (deployment platform concern); runtime policy enforcement (orthogonal to conformance verification); prompt injection detection (separate layer)

---

## Success Signal & Validation

**type:direction** | Product success: Enterprise DevOps can run APCV in CI/CD pre-merge; receives PASS/FAIL + auditable diff; can confidently promote Agent to production OR identify capability gaps for remediation

**type:direction** | Technical success: Framework discovery >95% accuracy; Probe execution <2 min; parameter tracing <1% overhead; Docker isolation 100% (no leakage); compliance_score matches manual audit review

**type:direction** | Market success: No existing tool fills this niche; EU AI Act 2026 compliance driver; 65% enterprise incident rate = strong purchase motivation

---

## Assumptions

**type:assumption** | LangGraph is statically parseable to sufficient accuracy (>95% tool discovery via AST @tool decorators)

**type:assumption** | Parameter-level tracing is sufficient for MVP conformance verification (sub-effects like file content changes are secondary)

**type:assumption** | Docker is available in target deployment environments (standard for modern CI/CD)

**type:assumption** | Declared policy (as YAML) is owner responsibility; no auto-inference from IAM/IaC in MVP

**type:assumption** | Compliance requirements (GDPR/SOX/ISO) primarily care about audit trail + deterministic verification, not behavioral guarantees

## Open Questions

**type:question** | How complete is LangGraph's public API for AST-based tool discovery? Are there private/implicit tools we'll miss?

**type:question** | What's the acceptable false-positive rate for Probe tests? (e.g., if 1 in 100 probes gives spurious failure, is that acceptable?)

**type:question** | Should Policy DSL be Rego/OPA-based (industry standard but learning curve) or custom YAML (simpler but non-standard)?

**type:question** | For multi-tenant SaaS future: how to isolate execution between different customers' Agents without cross-pollution?
