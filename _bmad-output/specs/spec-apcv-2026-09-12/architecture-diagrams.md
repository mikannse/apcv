## 数据流：完整验证周期

```
┌──────────────────┐
│  Agent 代码      │
│  + 策略 YAML     │
└────────┬─────────┘
         │
         ▼
    ┌────────────────────────────────────┐
    │  阶段 1：静态发现                  │
    │  ┌──────────────────────────────┐  │
    │  │ 1. 解析 Agent 代码（AST）    │  │
    │  │ 2. 抽取 @tool 装饰器         │  │
    │  │ 3. 发现运行时能力            │  │
    │  │ 4. 检测子 Agent              │  │
    │  └──────────────────────────────┘  │
    │           ↓                         │
    │  Tool SBOM（JSON）                  │
    │  ├─ tool_name, signature            │
    │  ├─ source（code/runtime/mcp）      │
    │  └─ parameters（name, type）        │
    └────────┬─────────────────────────────┘
             │
             ▼
    ┌────────────────────────────────────┐
    │  阶段 2：探针生成                  │
    │  ┌──────────────────────────────┐  │
    │  │ 1. 加载声明策略              │  │
    │  │ 2. 选择相关规则              │  │
    │  │ 3. 生成策略相对型            │  │
    │  │    越界测试用例              │  │
    │  └──────────────────────────────┘  │
    │           ↓                         │
    │  探针套件（20-30 个测试）           │
    │  ├─ probe_fs_1, probe_fs_2, ...     │
    │  ├─ probe_tool_1, probe_tool_2, ... │
    │  └─ probe_priv_1, ...               │
    └────────┬─────────────────────────────┘
             │
             ▼
    ┌────────────────────────────────────┐
    │  阶段 3：动态执行                  │
    │  （Docker 容器隔离）               │
    │  ┌──────────────────────────────┐  │
    │  │ 对每个探针：                 │  │
    │  │  1. 启动 Docker 容器         │  │
    │  │  2. 注入 wrapt 追踪器        │  │
    │  │  3. 运行探针（工具调用）     │  │
    │  │  4. 捕获执行轨迹             │  │
    │  │  5. 清理容器                 │  │
    │  └──────────────────────────────┘  │
    │           ↓                         │
    │  执行轨迹（JSONL）                  │
    │  ├─ timestamp                       │
    │  ├─ probe_id                        │
    │  ├─ tool_called                     │
    │  ├─ args（参数）                    │
    │  ├─ result（success/error）         │
    │  └─ policy_violation（Y/N）         │
    └────────┬─────────────────────────────┘
             │
             ▼
    ┌────────────────────────────────────┐
    │  阶段 4：一致性检查                │
    │  ┌──────────────────────────────┐  │
    │  │ 1. 比对 SBOM 与轨迹          │  │
    │  │ 2. 找出未声明工具            │  │
    │  │ 3. 检查参数范围              │  │
    │  │ 4. 应用策略规则              │  │
    │  └──────────────────────────────┘  │
    │           ↓                         │
    │  违规项与差异报告                   │
    │  ├─ tool、severity、reason          │
    │  ├─ 参数违规                        │
    │  ├─ 隐藏能力                        │
    │  └─ compliance_score (0-100)        │
    └────────┬─────────────────────────────┘
             │
             ▼
    ┌────────────────────────────────────┐
    │  阶段 5：策略校验                  │
    │  ┌──────────────────────────────┐  │
    │  │ 应用严重级别规则：           │  │
    │  │ - critical 违规 → FAIL       │  │
    │  │ - warning → WARN             │  │
    │  │ - info → PASS（无 critical） │  │
    │  └──────────────────────────────┘  │
    │           ↓                         │
    │  VERDICT（判定）：PASS | FAIL | WARN│
    │  + 详细报告（JSON/PDF/HTML）       │
    └────────┬─────────────────────────────┘
             │
             ▼
    ┌──────────────────────────┐
    │  输出与部署门禁          │
    │  ├─ CI/CD: exit 0 或 1   │
    │  ├─ 报告：PDF/JSON/HTML  │
    │  ├─ 审计日志：可追溯     │
    │  └─ 看板：已更新         │
    └──────────────────────────┘
```

## 四层工具发现模型

```
Agent 代码库
  │
  ├─ Layer 1: MCP 工具
  │  ├─ 读取 MCP Server 的 manifest.json
  │  ├─ 解析声明的工具
  │  └─ 抽取工具签名
  │
  ├─ Layer 2: 框架定义工具
  │  ├─ AST 解析：查找 @tool 装饰器
  │  ├─ 抽取函数签名（参数、返回类型）
  │  ├─ 发现参数约束（类型注解、docstring）
  │  └─ 构建 ToolRegistry
  │
  ├─ Layer 3: 运行时内建能力
  │  ├─ 检测框架隐式工具（如 code_execute、file_access）
  │  ├─ 扫描常见模式（os.system、subprocess 等）
  │  ├─ 识别框架提供的工具函数
  │  └─ 加入 Tool SBOM（标记为 "runtime-implicit"）
  │
  └─ Layer 4: 子 Agent 委派
     ├─ 查找子 Agent 实例化
     ├─ 递归对子 Agent 代码执行发现
     ├─ 标记继承的能力
     └─ 追踪 agent 层级
             │
             ▼
        ┌──────────────────┐
        │  统一的 Tool     │
        │  SBOM (JSON)     │
        │  100% 完整的     │
        │  能力清单        │
        └──────────────────┘
```

## 参数追踪与 Wrapt 集成

```
Agent 代码
  │
  ├─ 工具定义
  │  │
  │  def read_file(path: str) → str:
  │      """读取文件内容"""
  │      return open(path).read()
  │
  │
  ├─ 插桩层（wrapt）
  │  │
  │  @trace_parameters  ◄─── 运行时注入的装饰器
  │  def read_file(path: str) → str:
  │      trace_record = {
  │          "timestamp": now,
  │          "function": "read_file",
  │          "params": {"args": [path]},
  │      }
  │      try:
  │          result = original_read_file(path)
  │          trace_record["result"] = result
  │          return result
  │      finally:
  │          TRACE_LOG.append(trace_record)
  │
  │
  └─ 在 Docker 容器中执行
     │
     轨迹输出（JSONL）
     {
       "timestamp": "2026-09-12T10:00:01.234Z",
       "tool": "read_file",
       "args": ["/etc/passwd"],
       "result": "success",
       "policy_violation": true,
       "violation_reason": "path not in allowed_paths"
     }

     轨迹被收集，并与策略进行匹配比对
```

## 多容器并行执行

```
探针套件（20-30 个探针）
  │
  ├─ 探针 1 ────┐
  ├─ 探针 2 ────┤
  ├─ 探针 3 ────┼──► ThreadPoolExecutor(max_workers=4)
  ├─ 探针 4 ────│
  └─ ...         │
     └─ 探针 N ─┘
        │
        ▼
   ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
   │  Docker 1        │  │  Docker 2        │  │  Docker 3        │  │  Docker 4        │
   │ (probe_fs_1)     │  │ (probe_fs_2)     │  │ (probe_tool_1)   │  │ (probe_priv_1)   │
   │                  │  │                  │  │                  │  │                  │
   │ 隔离文件系统     │  │ 隔离文件系统     │  │ 隔离文件系统     │  │ 隔离文件系统     │
   │ 无网络           │  │ 无网络           │  │ 无网络           │  │ 无网络           │
   │ 30s 超时         │  │ 30s 超时         │  │ 30s 超时         │  │ 30s 超时         │
   │ 轨迹已记录       │  │ 轨迹已记录       │  │ 轨迹已记录       │  │ 轨迹已记录       │
   └──────────────────┘  └──────────────────┘  └──────────────────┘  └──────────────────┘
        │                     │                     │                     │
        ▼                     ▼                     ▼                     ▼
   轨迹 1                 轨迹 2                 轨迹 3                 轨迹 4

   聚合结果
   ├─ 收集全部轨迹
   ├─ 汇总违规项
   ├─ 计算合规评分
   └─ 生成报告
```

## CLI 到 CI/CD 的集成

```
开发者的 Git 工作流
  │
  git commit → git push
  │
  ▼
GitHub Actions（或 GitLab CI）
  │
  stages:
    - test
    - security  ◄─── APCV 在此运行
    - deploy

  ┌─────────────────────────────────────┐
  │ 一致性检查阶段                      │
  ├─────────────────────────────────────┤
  │                                     │
  │ apcv validate \                     │
  │   --agent langgraph:./agent.py \   │
  │   --policy ./policy.yaml \          │
  │   --output sarif > results.sarif    │
  │                                     │
  │ 退出码：0（PASS）或 1（FAIL）       │
  │                                     │
  │ 后置动作：在 PR 上评论              │
  │ "✅ Agent 符合策略"                 │
  │ 或                                  │
  │ "❌ Agent 违反策略：                │
  │  - 未声明的 bash 工具"              │
  └─────────────────────────────────────┘
         │
         ▼
    PASS → 继续部署
    FAIL → 阻止合并，通知开发者
```
