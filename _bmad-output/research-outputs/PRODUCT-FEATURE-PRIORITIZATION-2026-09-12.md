## P0 - MVP 核心功能

这些功能必须在 MVP 中完成。

### F1. 工具发现（4 层整合）

**优先级**：P0（MVP 核心，所有其他功能的基础）

**定义**：
```
从 Agent 代码和运行时同时提取工具列表
  - 静态层：AST 解析 @tool 装饰器
  - 动态层：运行时拦截工具调用
  - 对比层：发现隐藏能力和差异
  - 输出：结构化的 Tool SBOM
```

**依赖**：无

**工作量**：中（估计 3-4 天）

**验收标准**：
```
✅ 能发现 100% 的 LangGraph 工具
✅ AST 解析准确率 > 95%
✅ 运行时拦截零遗漏
✅ 静态 vs 运行时对比工作正常
✅ 处理时间 < 10 秒
✅ 支持异步函数
```

**交付物**：
- `ToolDiscovery` 类
- 单元测试
- LangGraph 适配器（基础）

### F2. Policy DSL 和验证

**优先级**：P0（MTV 核心，定义验证的"目标"）

**定义**：
```
YAML 格式的政策声明语言
  - 工具限制（allowed_tools、denied_tools）
  - 文件系统限制（allowed_paths、denied_paths）
  - 网络限制（enabled/disabled）
  - 权限限制（privilege_level）
  - 自定义约束

验证：政策格式是否正确、逻辑是否一致
```

**依赖**：无

**工作量**：低（估计 1-2 天）

**验收标准**：
```
✅ 支持所有必要的约束类型
✅ YAML 格式验证工作正常
✅ 清晰的错误消息
✅ 至少 5 个示例 policy 文件
✅ 文档详细
```

**交付物**：
- `Policy` 类和验证器
- Policy YAML Schema 定义
- 示例 policy 文件集
- 文档和快速开始指南

### F3. Probe 生成和执行

**优先级**：P0（MVP 核心，实现验证）

**定义**：
```
生成针对性的测试用例（Probe）
  - 从规则库选择与 Policy 相关的 Probe
  - 在隔离环境中执行每个 Probe
  - 记录执行结果（通过/失败/异常）
  
Policy-Relative 特性：
  - Probe 内容根据 Policy 动态调整
  - 不是固定的"危险操作"清单
  - 针对性强，误报率低
```

**依赖**：F2（需要 Policy 定义）

**工作量**：中（估计 3-4 天）

**验收标准**：
```
✅ Probe 规则库：20-30 个规则
✅ 覆盖场景：
   - 文件系统越权（5-10 个）
   - 工具调用越权（5-10 个）
   - 权限提升（3-5 个）
   - 能力合成（3-5 个）
✅ 动态生成：能根据 Policy 筛选 Probe
✅ 执行成功率：100%（记录失败原因）
✅ 规则文档清晰
```

**交付物**：
- `ProbeGenerator` 类
- Probe 规则库（YAML 格式，20-30 条）
- Probe 执行逻辑
- 规则文档和设计说明

### F6. 符合性检查和评分

**优先级**：P0（MVP 核心，输出核心判决）

**定义**：
```
对比 Policy 和执行结果
  - 工具调用是否符合允许列表
  - 参数是否在范围内
  - 是否有隐藏能力（风险！）
  - 计算符合度分数（0-100）

输出：
  - Verdict：PASS / FAIL / WARNING
  - Compliance Score：0-100
  - Violations：详细的违规列表
  - Recommendations：修复建议
```

**依赖**：F5（需要执行追踪）+ F2（需要 Policy）

**工作量**：低（估计 1-2 天）

**验收标准**：
```
✅ 能识别所有类型的违规
✅ 符合度分数算法合理
✅ 违规报告清晰和可操作
✅ 支持不同严重级别（critical/high/medium/low）
✅ 建议有具体的修复步骤
```

**交付物**：
- `ConformanceChecker` 类

## 优先级变更流程

如果 MVP 进行中需要优先级调整：

```
优先级升级：
  将 P1 功能移到 P0
  → 必须删除其他 P0 功能（保持范围平衡）
  → 征求项目管理层同意

优先级降级：
  将 P0 功能延后到 P1
  → 可能影响 MVP 完整性
  → 需要评估影响

新增功能：
  全部进入 P2（未来方向）
  → 除非是严重的 bug 或法规要求
```

## 使用指南

### 对于项目经理

```
跟踪进度：
  ✓ 统计完成的功能数 / P0 总数
  ✓ 了解每个功能的依赖关系
  ✓ 发现阻挡（如果某个功能卡住，哪些下游功能受影响）
  
例如：
  如果 F4（隔离执行）卡住
  → F5、F6、F7、F8、F9 都被阻挡
  → 立即解决 F4 是优先

调整范围：
  如果进度落后，先完成 F1-F9（核心）
  延后 F10-F11（文档和测试）到 P1
```

### 对于开发团队

```
推进顺序：
  1. 完成 F1（工具发现）- 这是基础
  2. 完成 F2（Policy DSL）- 定义验证目标
  3. 完成 F3（Probe 生成）- 产生测试用例
  4. 完成 F4（隔离执行）- 安全执行
  5. 完成 F5（参数追踪）- 审计日志
  6. 完成 F6（符合性检查）- 核心逻辑
  7. 并行 F7（CLI）、F8（UI）、F9（报告）
  8. 最后 F10（文档）、F11（测试）

并行工作：
  一旦 F1 和 F2 完成，可以并行开发 F3、F4、F5
  一旦 F6 完成，可以并行开发 F7、F8、F9
```

### 对于 QA 团队

```
测试优先级：
```
