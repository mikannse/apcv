## Key Constraints from Prior Work

- **Framework Choice**: LangGraph priority (MVP), extensible adapter pattern for others
- **Probe Strategy**: Parameter-Level Probe (core) + LLM-Driven (supplement)
- **Parameter Tracking**: wrapt library for tool call interception, <1% overhead
- **Data Persistence**: JSON files in `.apcv/reports/` directory
- **Execution Isolation**: Docker sandbox for probe execution
- **Output Format (CLI)**: Table display to terminal + JSON persistence
- **Coverage**: Four security boundaries (Tool, Runtime, Network, Identity) in MVP

---

## Architecture Decisions (Final)

### AD-1: Three-Layer Functional Architecture
- **Status**: ADOPTED
- **Rationale**: Mirrors Agent capability verification process with clear separation of concerns
- **Binds**: System structure and data flow

### AD-2: Four Independent Scanners (Tool/Runtime/Network/Identity)
- **Status**: ADOPTED
- **Rationale**: Separation of concerns, extensibility for new boundary types
- **Binds**: Scan layer internal organization

### AD-3: SBOM Output as Independent Files + Index
- **Status**: ADOPTED
- **Rationale**: Scalability, on-demand loading, extensibility
- **Binds**: Storage structure, .apcv/sbom/ directory organization

### AD-4: Validate Layer — Independent Validators + Shared Infrastructure
- **Status**: ADOPTED
- **Rationale**: Code reuse, testability, extensibility
- **Binds**: Validator organization, shared modules (ProbeExecutor, ParameterTracer, etc.)

### AD-5: Decision Layer — Unified Conformance Engine
- **Status**: ADOPTED
- **Rationale**: Judgment is inherently cross-dimensional
- **Binds**: How validation results aggregate into final verdict

### AD-6: Framework Abstraction via Adapter Pattern
- **Status**: ADOPTED
- **Rationale**: Enables multi-framework support without core coupling
- **Binds**: FrameworkAdapter interface, LangGraphAdapter (MVP), future adapters

### AD-7: CLI Interface Design
- **Status**: ADOPTED
- **Command**: `apcv validate --agent --policy [--output] [--format] [--fail-on] [--workers] [--timeout]`
- **Output**: Table to stdout + JSON to .apcv/reports/
- **Exit Codes**: 0=PASS, 1=FAIL, 2=error

### AD-8: Output Format and Reporting
- **Status**: ADOPTED
- **Terminal**: Human-readable table
- **Persistent**: Full JSON with execution trace to .apcv/reports/{timestamp}_{agent_name}.json
- **On-Demand**: SARIF, PDF, HTML via --format flag

### AD-9: Policy DSL Design
- **Status**: ADOPTED
- **Format**: YAML with five sections (metadata + four boundaries)
- **Boundaries**: tool, runtime, network, identity
- **Each**: allowed list, denied list, constraints (paths, domains, etc.)

### AD-10: Web UI Architecture
- **Status**: ADOPTED
- **Backend**: FastAPI + file-based storage
- **Frontend**: React/Vue
- **Features**: Dashboard, policy editor, execution timeline, report export
- **Deployment**: Single-process MVP; future separation

### AD-11: Error Handling and Logging
- **Status**: ADOPTED
- **Three-tier**: Silent failures (log + continue), non-fatal (warning + continue), fatal (stop + exit 2)
- **Location**: .apcv/logs/ with structured JSON logging

## Research Outputs

### Tool Call Mechanism Research (COMPLETED)
- Parameter-level Probe chosen as core approach (vs LLM-driven)
- wrapt library confirmed as best choice (<1% overhead, mature)
- LangGraph and AgentScope tool call mechanisms analyzed

### SBOM Standards Research (COMPLETED)
- CycloneDX/SPDX studied but deemed MVP-overkill
- JSON Schema adopted as MVP format (sufficient, flexible)
- MVP SBOM includes: tool definitions, parameter constraints, runtime capabilities

### Open Source Survey (COMPLETED)
- No mature "Agent Policy Conformance" tool exists (market gap confirmed)
- LangGraph API can support tool discovery (via adapter)
- OPA/Rego suitable for policy engine
- Docker SDK appropriate for sandbox execution
