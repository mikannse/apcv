## 来自前期工作的关键约束

- **框架选择**: 优先支持 LangGraph（MVP），通过可扩展的适配器（Adapter）模式支持其他框架
- **探测（Probe）策略**: 参数级探测 Parameter-Level Probe（核心）+ LLM 驱动探测（补充）
- **参数追踪**: 使用 wrapt 库拦截工具调用，开销 <1%
- **数据持久化**: JSON 文件存放于 `.apcv/reports/` 目录
- **执行隔离**: 使用 Docker 沙箱执行探测
- **输出格式（CLI）**: 终端表格展示 + JSON 持久化
- **覆盖范围**: MVP 覆盖四道安全边界（Tool、Runtime、Network、Identity）

## 架构决策（最终）

### AD-1: 三层功能架构
- **状态**: ADOPTED
- **理由**: 与 Agent 能力验证流程相对应，关注点分离清晰
- **约束（Binds）**: 系统结构与数据流

### AD-2: 四个独立扫描器（Tool/Runtime/Network/Identity）
- **状态**: ADOPTED
- **理由**: 关注点分离，便于向新边界类型扩展
- **约束（Binds）**: 扫描层内部组织

### AD-3: SBOM 输出为独立文件 + 索引
- **状态**: ADOPTED
- **理由**: 可扩展、按需加载、便于演进
- **约束（Binds）**: 存储结构、.apcv/sbom/ 目录组织

### AD-4: Validate 层 — 独立验证器 + 共享基础设施
- **状态**: ADOPTED
- **理由**: 代码复用、可测试性、可扩展性
- **约束（Binds）**: 验证器组织方式、共享模块（ProbeExecutor、ParameterTracer 等）

### AD-5: Decision 层 — 统一一致性引擎（Conformance Engine）
- **状态**: ADOPTED
- **理由**: 判定天然跨维度
- **约束（Binds）**: 验证结果如何聚合为最终裁决

### AD-6: 通过 Adapter 模式实现框架抽象
- **状态**: ADOPTED
- **理由**: 在不与核心耦合的前提下支持多框架
- **约束（Binds）**: FrameworkAdapter 接口、LangGraphAdapter（MVP）、未来的各类适配器

### AD-7: CLI 接口设计
- **状态**: ADOPTED
- **命令**: `apcv validate --agent --policy [--output] [--format] [--fail-on] [--workers] [--timeout]`
- **输出**: 表格输出到 stdout + JSON 输出到 .apcv/reports/
- **退出码**: 0=PASS，1=FAIL，2=错误

### AD-8: 输出格式与报告
- **状态**: ADOPTED
- **终端**: 人类可读的表格
- **持久化**: 包含执行追踪（execution trace）的完整 JSON，输出到 .apcv/reports/{timestamp}_{agent_name}.json
- **按需生成**: 通过 --format 参数输出 SARIF、PDF、HTML

### AD-9: 策略 DSL 设计
- **状态**: ADOPTED
- **格式**: YAML，包含五个部分（metadata + 四个边界）
- **边界**: tool、runtime、network、identity
- **各边界**: allowed 列表、denied 列表、约束条件（路径、域名等）

### AD-10: Web UI 架构
- **状态**: ADOPTED
- **后端**: FastAPI + 基于文件的存储
- **前端**: React/Vue
- **功能**: 仪表盘（Dashboard）、策略编辑器、执行时间线、报告导出
- **部署**: MVP 为单进程；未来再做前后端分离

### AD-11: 错误处理与日志
- **状态**: ADOPTED
- **三级策略**: 静默失败（记录日志 + 继续执行）、非致命错误（警告 + 继续执行）、致命错误（停止 + 以 2 退出）
- **位置**: .apcv/logs/，采用结构化 JSON 日志

## 研究产出

### 工具调用机制研究（已完成）
- 选定参数级 Probe 作为核心方案（对比 LLM 驱动方案）
- 确认 wrapt 库为最佳选择（开销 <1%，成熟稳定）
- 分析了 LangGraph 与 AgentScope 的工具调用机制

### SBOM 标准研究（已完成）
- 研究了 CycloneDX/SPDX，但认为对 MVP 而言过于重量级
- 采用 JSON Schema 作为 MVP 格式（足够用、灵活）
- MVP SBOM 包含：工具定义、参数约束、运行时能力

### 开源调研（已完成）
- 目前没有成熟的 "Agent Policy Conformance" 工具（市场空白已确认）
- LangGraph API 可以支撑工具发现（通过 adapter）
- OPA/Rego 适合作为策略引擎
- Docker SDK 适合沙箱执行
